四、来源冲突时的取舍规则

  1. 节点名、界面显示名、分类、输入/输出（含类型、默认值、tooltip、可选项）、是否为输出节点、python_module：以 S6（节点数据集） 为准，因为它反映你机器上真实可用的节点。
  2. 中文用途说明：以 S2 官方中文文档 为准；中文缺失时保留英文原文并标记语言，不自行翻译冒充官方。
  3. 英文用途说明：以 S3 为准，缺失时退回 S6 的 description。
  4. S4 源码只用于补充与校对（例如某节点在哪个模块注册），不用来覆盖 S6 的输入/输出事实。
  5. 节点条目必须至少有一个可追溯来源；没有来源的条目一律剔除。

七、如何重建这些数据

  1. 抓取官方文档：使用 scripts/fetch_docs.mjs（Node 原生 fetch，无需第三方依赖）下载官方文档索引与逐节点 Markdown 到 vendor/docs/；下载结果记录在 vendor/docs/fetch-manifest.json（1032 篇中文、失败 0 篇）。
  2. 生成节点数据：运行 scripts/build_catalog.py（Python 3 标准库），解析 vendor/docs/node-index.json、vendor/docs/nodes/zh|en/*.md 与 节点数据集快照，输出 site/assets/nodes-data.js（window.COMFY_DATA），并写出 data/build-report.md 构建报告。
  3. 教程、术语与来源页：workflows.html、faq.html、sources.html 为静态 HTML，内容取自 S1–S6 并逐节标注来源；对应的结构化镜像保存在 site/assets/content-data.js（window.CW_CONTENT，仅供审计与二次开发，页面运行不依赖它）。
  4. 离线校验：直接双击 site/index.html 打开即可；本站不使用 fetch/XHR、不加载任何站外资源，因此断网（或开发者工具 Offline）下功能不变。站外来源链接需要联网。

相关证据文件：SPEC.md（项目契约）、data/build-report.md（构建报告）、audit/compliance-report.md（合规审计）、audit/verification-report.md（离线与交互验证）。
