常用工作流拆解

本页把 ComfyUI 官方教程里的常用工作流拆成「节点链路 → 关键参数 → 常见坑」：文生图、图生图、局部重绘、扩图、高清放大、LoRA、ControlNet，以及官方文档中确实存在的视频与音频工作流。

阅读约定：下面出现的 KSampler 这类等宽字体名称都是真实节点键名（来自节点数据集 与官方节点文档）；中文界面里显示的往往是中文译名，例如显示名 Load Checkpoint 对应真实节点名 CheckpointLoaderSimple。每个节点的完整输入/输出表格见 节点百科。

本页参数默认值全部来自官方中文节点文档或节点数据集，没有推断或补全。官方节点文档本身由 AI 生成，若与你的界面不符，请以 来源与合规 页列出的官方页面与源码为准。

1. 文生图（Text to Image）

官方教程的文生图流程是：加载默认工作流 → 安装 SD1.5 checkpoint → 编写提示词 → 点击 Queue（或 Ctrl + Enter）执行。看懂这条链路，是看懂其它工作流的基础。

节点链路

  1. CheckpointLoaderSimple （界面显示名：Load Checkpoint）：加载 checkpoint，并拆成 MODEL（主模型）、CLIP（文本编码器）、VAE（图像编解码器）三个输出端口。
  2. CLIPTextEncode （界面显示名：CLIP Text Encode (Prompt)） × 2：把提示词编码为 CONDITIONING。接到 KSampler 的 positive 的是正向提示词，接到 negative 的是负向提示词。
  3. EmptyLatentImage （界面显示名：Empty Latent Image）：生成指定尺寸与批次大小的空白潜空间（默认 width / height / batch_size = 512 / 512 / 1）。
  4. KSampler：去噪主节点，接收 MODEL、正负条件与潜空间图，输出采样后的 LATENT。
  5. VAEDecode （界面显示名：VAE Decode）：把 LATENT 解码为可保存的 IMAGE。
  6. SaveImage （界面显示名：Save Image）：输出节点，把图像以 PNG 保存到 ComfyUI 输出目录。

关键参数建议

参数 / 项建议与说明官方依据
steps 步数默认 20，范围 1~10000。官方说明：步数越多，结果越精确。KSampler 官方中文文档
cfg默认 8.0，官方建议 6-8：控制生成图像与输入条件的匹配程度。KSampler 官方中文文档
sampler_name / scheduler采样器影响生成速度与风格；调度器控制噪声的移除方式。数据集可选采样器 44 项、调度器 9 项（取自 节点数据集）。KSampler 文档 + 节点数据集
seed 种子默认 0。官方说明：使用相同的种子将生成相同的图像。KSampler 官方中文文档
denoise 降噪默认 1.0。文生图保持 1.0（从纯噪声开始去噪）。KSampler 官方中文文档
提示词写法尽量用英文；提示词之间用英文逗号分隔；尽量用短语而不是长句；权重写法 (golden hour:1.2)。文生图官方教程

常见坑

每次运行 KSampler 都会按 seed 使用不同的随机种子，所以同一提示词的结果每次都会不同（官方教程原文）。想复现某张图，先固定种子。

提示词要写“字面括号”时需转义：\(word\)；动态提示词 {day|night|morning} 会随机选一项，需要字面花括号时写 \{word\}（CLIPTextEncode 官方中文文档）。

2. 图生图（Image to Image）

官方教程的说法：图生图与文生图非常相似，只是多了一个输入参考图像作为条件——把参考图编码进潜空间，再让采样器在它的基础上重新绘制。

节点链路

  1. CheckpointLoaderSimple （界面显示名：Load Checkpoint）：提供 MODEL / CLIP / VAE。
  2. LoadImage （界面显示名：Load Image）：上传参考图像（输出 IMAGE，同时输出 MASK）。
  3. VAEEncode （界面显示名：VAE Encode）：把 IMAGE 编码成 LATENT，作为采样起点。
  4. CLIPTextEncode （界面显示名：CLIP Text Encode (Prompt)） × 2：正向与负向提示词。
  5. KSampler：关键参数是 denoise，图生图必须 小于 1。
  6. VAEDecode （界面显示名：VAE Decode） → SaveImage （界面显示名：Save Image）：解码并保存结果。

关键参数建议

参数 / 项建议与说明官方依据
denoise < 1denoise 值越小，生成图像与参考图像差异越小；值越大差异越大。图生图官方教程
denoise = 1潜空间图会变为完全随机的噪声，等同于空 Latent 图像节点的输出，参考图像的特征会全部丢失。图生图官方教程
denoise = 0官方说明：只有 denoise 为 0 时才完全不执行采样步。图生图官方教程
steps 与 denoise 的关系调低 denoise 不会减少实际执行的采样步数；ComfyUI 会按 steps / denoise（向下取整）构建调度表，再保留最后 steps + 1 个 sigma。若想在保持步长密度的情况下只采样部分噪声区间，把 steps 设为“运行步数 × denoise”。图生图官方教程（原文说明）

常见坑

教程示例：steps 20 + denoise 0.5 实际是在 40 步调度表的后半段执行 20 个采样步；想要“少步但同样密度”，应把 steps 设为 10（20 × 0.5），而不是只改 denoise。

参考图分辨率直接决定潜空间尺寸，也决定显存占用；先确认输入图尺寸，再调采样参数。

3. 局部重绘（Inpainting）

局部重绘解决的是“整张图基本满意，但某块区域要改”的问题：用遮罩（Mask）圈出要改的区域，只对这块区域重新生成。官方教程要求在工作流中连接 VAE Encode (for Inpainting) 节点。

节点链路（官方教程示例）

  1. CheckpointLoaderSimple （界面显示名：Load Checkpoint）：教程建议使用 inpainting 专用 checkpoint（例如 512-inpainting-ema.safetensors），过渡更自然。
  2. LoadImage （界面显示名：Load Image）：上传输入图像。教程示例图自带 alpha 透明度通道，可直接当作遮罩。
  3. VAEEncodeForInpaint （界面显示名：VAE Encode (for Inpainting)）：接收 pixels、vae、mask，输出带噪声遮罩的 LATENT；grow_mask_by（扩展遮罩）默认 6。
  4. CLIPTextEncode （界面显示名：CLIP Text Encode (Prompt)） × 2：描述“要在遮罩区域里画什么”。
  5. KSampler → VAEDecode （界面显示名：VAE Decode） → SaveImage （界面显示名：Save Image）。

另一种核心节点写法

也可以用 InpaintModelConditioning：它接收 positive、negative、vae、pixels、mask（以及 noise_mask，默认 true），一次输出加工后的 positive、negative 与 latent，再交给 KSampler。

常见坑

遮罩有两种来源：输入图自带的 alpha 通道；或使用 ComfyUI 的遮罩编辑器（Mask Editor）手动绘制（官方教程）。教程示例图已含 alpha 通道，所以不需要手绘。

grow_mask_by / 扩展遮罩：数值越大，修复影响的区域越大（官方文档）；数值太小容易在边界留下生硬的接缝。

用普通 checkpoint 也能跑重绘，但官方教程明确对比指出：inpainting 专用模型对生成区域的控制更好、过渡更自然。

4. 扩图（Outpainting）

官方教程写得很直接：扩图本质上就是一个局部重绘（Inpaint）工作流，只不过“用来构建遮罩（Mask）的节点不同”。

节点链路

  1. LoadImage （界面显示名：Load Image）：上传要向外扩展的图像。
  2. ImagePadForOutpaint （界面显示名：Pad Image for Outpainting）：控制扩展方向与范围，输出扩展后的 IMAGE 与对应的 MASK（left / top / right / bottom 默认 0，feathering 默认 40）。
  3. VAEEncodeForInpaint （界面显示名：VAE Encode (for Inpainting)）：把扩展图和遮罩编码成 LATENT。
  4. KSampler → VAEDecode （界面显示名：VAE Decode） → SaveImage （界面显示名：Save Image）。
  5. 模型：教程同样使用 inpainting 专用 checkpoint（512-inpainting-ema.safetensors），并提示加载后在 Load Checkpoint（中文界面：加载模型）中选中本地已安装的模型。

常见坑

扩展区域完全由 ImagePadForOutpaint 的参数决定：四个方向的像素量决定“补多大的边”，feathering 决定过渡的柔和程度。

扩图后画布变大，显存占用随之增加；扩展方向若与提示词描述的场景不符，边缘容易出现风格断层。

5. 高清放大（Upscale）

官方教程的核心组件是“加载放大模型”和“缩放图像（使用模型）”：前者加载放大模型，后者用该模型把图像放大。放大模型放在 ComfyUI/models/upscale_models（教程示例使用 4x-ESRGAN.pth）。

节点链路（基础放大）

  1. LoadImage （界面显示名：Load Image）：上传要放大的图像。
  2. UpscaleModelLoader （界面显示名：Load Upscale Model）：选择放大模型（教程：确保加载的是 4x-ESRGAN.pth）。
  3. ImageUpscaleWithModel （界面显示名：Upscale Image (using Model)）：接收 upscale_model 与 image，输出放大后的 IMAGE。
  4. SaveImage （界面显示名：Save Image）：保存结果。

组合流水线（官方教程）

  1. 把文生图的输出图像直接连接到放大节点，形成“生成 + 增强”流水线。
  2. 链式放大：串联多个放大节点（例如 2x → 4x）实现更高倍率。
  3. ImageScaleBy （界面显示名：Upscale Image By）：不依赖模型，按 scale_by（默认 1）与 upscale_method（nearest-exact / bilinear / area / bicubic / lanczos）直接缩放。
  4. ImageScaleToTotalPixels （界面显示名：Scale Image to Total Pixels）：按总像素数缩放（megapixels 默认 1、resolution_steps 默认 1）。官方放大指南提到：对 SeedVR2 这类模型，放大前先用它把图像缩小到 0.35 百万像素效果更好。

常见坑

官方放大指南强调“放大（提高分辨率）”与“增强（重建细节）”是两件事，最佳实践常把两步结合使用。

教程建议：不同放大模型在特定图像类型上表现更好，建议多种模型都测一测；链式放大和“先小图后放大”是常见的成本/时间优化策略。

6. LoRA

官方教程把 LoRA 比作“滤镜”：在不重新训练整个大模型的前提下，给图像加上特定风格、角色特征或细节。LoRA 模型放在 ComfyUI/models/loras（LoraLoader 会自动检测该文件夹，包括子文件夹）。

节点链路

  1. CheckpointLoaderSimple （界面显示名：Load Checkpoint）：提供基础 MODEL 与 CLIP。
  2. LoraLoader （界面显示名：Load LoRA (Model and CLIP)）：接收 model、clip、lora_name、strength_model、strength_clip，输出应用了 LoRA 的 MODEL 与 CLIP。
  3. CLIPTextEncode （界面显示名：CLIP Text Encode (Prompt)） × 2：提示词编码（使用 LoraLoader 输出的 CLIP）。
  4. KSampler（使用 LoraLoader 输出的 MODEL）→ VAEDecode （界面显示名：VAE Decode） → SaveImage （界面显示名：Save Image）。
  5. 只需要调整模型、不需要改 CLIP 时，可用 LoraLoaderModelOnly （界面显示名：Load LoRA）：它只接收 model，输出 MODEL。

关键参数建议（LoraLoader 官方中文文档）

参数说明官方依据
model通常用于连接基础模型。LoraLoader 文档
clip通常用于连接 CLIP 模型。LoraLoader 文档
lora_name选择要使用的 LoRA 模型名称。LoraLoader 文档
strength_model 模型强度取值范围 -100.0 到 100.0，日常图像生成通常在 0~1 之间使用。数值越高，模型调整效果越明显。LoraLoader 文档
strength_clip CLIP 强度取值范围 -100.0 到 100.0，日常图像生成通常在 0~1 之间使用。数值越高，调整效果越明显。LoraLoader 文档

叠加多个 LoRA

官方文档说明该节点支持链式连接：把多个 LoraLoader 串联即可应用多个 LoRA 模型（官方另有《应用多个 LoRA 示例》教程）。

常见坑

文本嵌入（embedding）与模型架构必须匹配：官方文档明确举例——为 SD1.5 设计的嵌入无法正确用于 SDXL 模型。LoRA 同理，需与所选基础模型架构一致。

LoRA 文件要放进 models/loras，否则 lora_name 下拉列表里找不到它。

7. ControlNet

ControlNet 用一张“条件图像”（边缘图、深度图、姿态关键点等）来控制生成结果，减少反复试错的提示词试验。官方教程里的核心节点是 Load ControlNet 与 Apply ControlNet。

节点链路

  1. LoadImage （界面显示名：Load Image）：上传控制用的参考图（教程示例为涂鸦图）。
  2. 预处理（按需）：教程说明 Comfy Core 节点中不包含所有类型的预处理器，实际使用常借助自定义节点（如 ComfyUI ControlNet aux、ComfyUI-Advanced-ControlNet）。已收录 comfyui_controlnet_aux（64 个节点），真实节点名如 CannyEdgePreprocessor、OpenposePreprocessor、DepthAnythingV2Preprocessor、LineArtPreprocessor、HEDPreprocessor 等（名称取自节点数据集）。
  3. ControlNetLoader （界面显示名：Load ControlNet Model）：加载 ControlNet 模型（models/controlnet 目录下的模型会被自动识别）。
  4. ControlNetApplyAdvanced （界面显示名：Apply ControlNet）：接收 positive、negative、control_net、image，以及 strength / start_percent / end_percent（可选 vae），输出处理过的正向与负向条件。
  5. KSampler → VAEDecode （界面显示名：VAE Decode） → SaveImage （界面显示名：Save Image）。
  6. VAELoader （界面显示名：Load VAE）：教程示例使用独立 VAE（vae-ft-mse-840000-ema-pruned.safetensors），按模型作者建议替换 checkpoint 内置 VAE。

关键参数建议

参数 / 项建议与说明官方依据
strength 控制强度默认 1。教程：应用 ControlNet 的强度，越大则 ControlNet 对生成图像的影响越大。ControlNet 官方教程
start_percent默认 0。教程：取值 0.2 表示引导在扩散过程完成 20% 时开始影响图像生成。ControlNet 官方教程
end_percent默认 1。教程：取值 0.8 表示引导在扩散过程完成 80% 时停止影响图像生成。ControlNet 官方教程
control_net / image分别接入 ControlNetLoader 的模型输出与参考图；模型要与基础模型版本匹配（教程示例为 SD1.5 的 ControlNet V1.1）。ControlNet 官方教程

说明：官方教程正文明确点名的是加载节点与条件/潜空间节点（DualCLIPLoader、UNETLoader、EmptyHunyuanLatentVideo、Wan22ImageToVideoLatent、WanFirstLastFrameToVideo、LoadImage）以及保存节点；中间的 KSampler → VAEDecode 属于核心采样链路，节点名同样取自官方节点文档与节点数据集。

8.1 Wan2.2 TI2V 5B（文生视频 / 图生视频混合版本）

  1. UNETLoader （界面显示名：Load Diffusion Model）（界面显示名：Load Diffusion Model）：加载扩散模型权重（weight_dtype 可选 default / fp8_e4m3fn / fp8_e4m3fn_fast / fp8_e5m2）。
  2. DualCLIPLoader （界面显示名：Load CLIP (Dual)）：加载双文本编码器，type 选项包含 hunyuan_video、flux、sd3、ltxv、ace 等。
  3. LoadImage （界面显示名：Load Image）：做图生视频时上传起始图像。
  4. Wan22ImageToVideoLatent：从图像创建视频潜表示（默认 1280 × 704，length 49，batch_size 1）。教程原文：可在该节点中调整尺寸设置和视频总帧数（length）。
  5. KSampler → VAEDecode （界面显示名：VAE Decode） → CreateVideo （界面显示名：Create Video）（images + fps，默认 30）→ SaveVideo （界面显示名：Save Video）（video + filename_prefix，默认 video/ComfyUI，format 默认 auto）。
  6. 教程 Tip：Wan2.2 5B 版本配合 ComfyUI 原生 offloading，应能很好地适配 8GB 显存。

8.2 Wan2.2 14B FLF2V（首尾帧生视频）

  1. LoadImage （界面显示名：Load Image） × 2：分别上传首帧与尾帧（教程示例文件名 video_wan2_2_14B_flf2v_start_image.png 与 ..._end_image.png）。
  2. WanFirstLastFrameToVideo：接收 positive、negative、vae 与 width / height / length / batch_size（默认 832 × 480，length 81）。教程提示：调整该节点中的尺寸设置。
  3. KSampler → VAEDecode （界面显示名：VAE Decode） → CreateVideo （界面显示名：Create Video） → SaveVideo （界面显示名：Save Video）。

8.3 混元视频（HunyuanVideo）

  1. DualCLIPLoader （界面显示名：Load CLIP (Dual)）：加载文本编码器（教程要求确认其中已加载对应模型）。

  3. KSampler → VAEDecode （界面显示名：VAE Decode） → CreateVideo （界面显示名：Create Video） → SaveVideo （界面显示名：Save Video）。

9. 音频工作流（官方原生示例）

9.1 ACE-Step：文本到音频（音乐生成）

  1. CheckpointLoaderSimple （界面显示名：Load Checkpoint）：教程要求确保加载 ace_step_v1_3.5b.safetensors。
  2. TextEncodeAceStepAudio：接收 clip、tags（音乐风格等标签）、lyrics（歌词）、lyrics_strength（默认 1）。
  3. EmptyAceStepLatentAudio （界面显示名：Empty Ace Step 1.0 Latent Audio）：设置生成音乐的时长（seconds，默认 120）。
  4. KSampler → VAEDecodeAudio （界面显示名：VAE Decode Audio） → SaveAudio （界面显示名：Save Audio (FLAC) (DEPRECATED)）。

9.2 ACE-Step：音频到音频

  1. CheckpointLoaderSimple （界面显示名：Load Checkpoint）：同样加载 ace_step_v1_3.5b.safetensors。
  2. LoadAudio （界面显示名：Load Audio）：上传输入音频。
  3. VAEEncodeAudio （界面显示名：VAE Encode Audio）：把音频编码为潜空间（audio + vae）。
  4. KSampler：教程原文——可通过控制 KSampler 的 denoise 参数来调整与原始音频的差异程度。
  5. TextEncodeAceStepAudio（可填 tags / lyrics，教程提示：提供歌词对音频编辑非常重要）→ VAEDecodeAudio （界面显示名：VAE Decode Audio） → SaveAudio （界面显示名：Save Audio (FLAC) (DEPRECATED)）。
